# 文档目录说明

**更新时间**：2026-05-08  
**目录原则**：外层只保留当前有效、可用于产品沟通和后续实施的材料；历史过程稿、旧架构、旧 prompt 草案和阶段性讨论统一放入归档目录。

## 当前有效文档

| 文档 | 用途 |
| --- | --- |
| `当前方案与产品交接文档.md` | 当前最完整的项目交接文档，面向产品、业务和后续实施团队 |
| `后端提取与检查分层方案.md` | 后端“两层四块”检查逻辑、A2 语义归一和后续代码拆分方案 |
| `报告页展示逻辑.md` | 前端报告页的业务阅读逻辑、三类检查结果和证据预览思路 |
| `产品交接汇报材料/` | 按华为式结构化汇报风格生成的 PPTX、预览图和生成脚本 |

## 归档目录

`归档/历史方案与过程文档/` 存放历史材料，包括：

- 早期 PRD 和旧版架构。
- 旧版 prompt 重构草案。
- 场景规则矩阵、字段簇规则草案等过程材料。
- 领导对齐和前端报告演进过程笔记。
- 当前实现已不再完全采用的历史方案。

归档材料可作为溯源和思路参考，但对外沟通、产品交接和后续开发应优先以外层当前有效文档为准。

## 后续维护规则

1. 新增文档如果代表当前有效方案，应放在 `docs` 外层，并使用中文可理解文件名。
2. 阶段性草案、过程分析、已经被新方案替代的材料，应及时移动到 `归档/历史方案与过程文档/`。
3. 面向领导或产品沟通的材料，应优先更新 `当前方案与产品交接文档.md` 和 `产品交接汇报材料/`。
4. 后端检查逻辑变更，应优先更新 `后端提取与检查分层方案.md`。
5. 前端报告交互和展示逻辑变更，应优先更新 `报告页展示逻辑.md`。
